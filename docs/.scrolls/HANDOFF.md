## Recent bugs fixed (context for debugging similar issues)
1. **compareImage crash** — used shapeLabel(a) (expects .paras) on image objects. Fixed: use a.name directly.
2. **Master/layout panel blank names** — layoutBox() fallback + try/catch hardening around every per-slide sub-parser.
3. **Syntax error / whole-class eval failure** — a multi-line edit deleted a const opener line, breaking the whole class silently. Always grep to confirm exactly one definition survives after a multi-line edit.
4. **Embedded-fonts race condition** — a second independent JSZip.loadAsync raced on first mount. Fixed by passing known fonts directly for the sample deck.
5. **Hyperlink targets got ppt/slides/ prepended** — parseRelsFor now detects TargetMode=External / absolute URI schemes before resolving as a local path.
6. **Merge-plan/merge-choice key mismatch** — export used an ad-hoc key instead of the canonical pairKey + '::' + diffKey scheme setMergeChoice actually writes to.
7. **MOVED tag inverted (this session, two rounds to fix)** — round 1 replaced the local leftover-pass heuristic with a patience-sort LIS, which was an improvement but still arbitrary on ties (decreasing bIdx sequences with two length-1 chains): it kept whichever chain the sort processed last, which happened to be the wrong one. Round 2 fix: replaced patience-sort with an O(n^2) DP that tracks a secondary same-position (aIdx===bIdx) count per chain and tie-breaks on it when reconstructing the best chain — verified via a direct unit test (`markMovedByLIS` regression test) reproducing the exact 5→5-vs-6→4 tie case. **Lesson: LIS/patience-sort is not just "find *a* longest chain" when the semantic meaning of ties matters — when two equally-long chains exist, be explicit about which one the domain prefers, and encode that preference into the DP's comparison rather than relying on insertion-order behavior of a generic algorithm.**

## Update (this session — Export dropdown fix, then touch ghost / report import / live push)
- Fixed a verifier-caught bug from the previous session's export-format additions: the Export dropdown panel used `right:0`, which overflowed off-screen to the left when the `<details>` toggle ended up near the viewport's left edge (e.g. after flex-wrap on a narrower layout). Switched to `left:0` with a capped `max-width`. **Lesson for dropdown/menu panels anchored to a toggle inside a `flex-wrap` row: don't assume the toggle is near the right edge of the viewport — anchor from the side that can never go negative (`left:0` off a `position:relative` toggle), not the side that assumes a specific screen position.**
- Then shipped, with Red/Green self-tests written alongside each: touch drag-preview ghost for batch reorder, report-JSON round-trip import (`key`-based, tolerant of older exports), and live push attempts to Slack (webhook, no-cors form POST workaround), Notion (blocks API), and Confluence (REST API GET-then-PUT) — all three implemented as real fetch calls, with Notion/Confluence expected to usually fail on CORS from a pure client-side page (caught gracefully, pointing back at the existing file-based exports as the working fallback). Slack is the one most likely to actually succeed client-side.
- Live-push credentials (Slack webhook URL, Notion token/page ID, Confluence base URL/email/token/page ID) are intentionally kept in component state ONLY — never added to the `persistState()`/`restorePersisted()` payload, and the modal says so. Do not add these fields to localStorage persistence without an explicit user ask; secrets in localStorage is a real risk this project has so far avoided.

## Update (this session — merge/overwrite import, Confluence replace/append, Slack delivery confirmation, opt-in creds persistence)

## Update (this session — single-comment delete, bulk comment/history confirmation gates)
- The confirmation-gate pattern (`request*` sets a confirm-flag/target → modal shows → `confirm*Yes` performs the action and clears the flag, `cancel*` just clears the flag) is now used identically for THREE destructive bulk actions: reviewers (`confirmRemoveReviewers: boolean`), comments (`confirmDeleteComments: string|null` — holds the pairKey being confirmed, since comments are scoped per-slide), history (`confirmClearHistory: boolean`).
