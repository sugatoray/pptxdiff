## Update (2026-07-21 — fixed off-slide element bug in the pptxgenjs fixture generator)
- **Bug**: after switching to `pptxgenjs` (see update below), the user reported elements in `sample_*.pptx` render outside the slide bounds. Root cause: `pptx.layout = 'LAYOUT_16x9'` is pptxgenjs's built-in preset, which is **10 x 5.625in**, NOT the 13.333 x 7.5in modern PowerPoint widescreen size every coordinate in the script was authored against (confirmed via `unzip -p file.pptx ppt/presentation.xml | grep sldSz` showing `cx="9144000" cy="5143500"` = 10x5.625in, vs. the expected `12191695 x 6858000` = 13.333x7.5in). Nearly every shape's `x`/`y`/`w`/`h` therefore extended past the actual slide edges.
- **Fix**: `pptx.defineLayout({ name, width: 13.333, height: 7.5 })` + `pptx.layout = 'PPTXDIFF_16X9'` — a custom layout matching what the coordinates actually assume, instead of relying on the built-in (differently-sized) preset name. Also fixed a real leftover bug the linter caught: the slide-1 footer had `isBefore ? 'Confidential — 2026' : 'Confidential — 2026'` (identical text both branches, a copy-paste leftover from an earlier edit) — simplified to a plain string.
- **New permanent guard**: added `checkBounds(label, {x,y,w,h})`, called via `placedText`/`placedImage`/`placedTable`/`placedChart` wrappers at every element-placement call site — throws immediately at generation time if any shape's bounds exceed the slide's declared width/height. This is exactly the kind of non-trivial position-arithmetic logic (WISDOM.md/ponytail conventions) that needs a standing check, not just a one-time fix; it will catch a repeat of this exact mistake (or a future coordinate typo) before a file ships.
- **Verified**: `uv run --with python-pptx` — walked every shape in every slide of both regenerated files and compared `shape.left/top/width/height` against `presentation.slide_width/slide_height`; **zero out-of-bounds shapes** on either file (down from the wrong-canvas-size bug). Content-type/relationship audit (same technique as the earlier SmartArt incident) still comes back clean. Slide size confirmed correct: 13.333 x 7.5in.
