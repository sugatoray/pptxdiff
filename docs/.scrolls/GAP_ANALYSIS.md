# GAP_ANALYSIS.md — Implementation Gaps

Concrete, testable gaps between what SPEC.md describes and a fully "real" implementation. See GAP_CONTEXT.md for the reasoning behind each.

## Rendering fidelity
- [ ] Chart/SmartArt/media parts generated by `sample-pptx.js` are minimal-valid OOXML — not guaranteed to render pixel-perfect in `@aiden0z/pptx-renderer`; some slides may show "Schematic" instead of "Rendered" badge.
- [ ] Master/layout thumbnails are schematic dashed-rect outlines only (position/size of placeholders), not actual rendered master/layout art (background fills, master-level text styles, theme colors are not drawn).
- [ ] No zoom/pan on individual slide previews (only prev/next stepping).

## Diff engine
- [ ] Theme-color (schemeClr) resolution is a hardcoded partial map (tx1/dk1/tx2/dk2/bg1/lt1/accent1 only) in `readRunFmt` — other scheme colors (accent2-6, hlink, folHlink) fall back to the shape's existing color rather than resolving the real theme value.
- [ ] Table cell formatting diff is capped at 6 shown differences + "+N more" note — no way to see all of them without exporting.
- [ ] Animation diff is a single signature-string comparison (type:target:preset joined) — doesn't diff individual animation *parameters* (duration, delay, motion path coordinates).
- [ ] No diff for: slide size/aspect ratio changes between decks, section headers (`p:sectionLst`), custom shows, comments embedded in the original pptx (PowerPoint's own comment feature, distinct from this tool's reviewer comments), OLE objects, 3D models, ink/drawing annotations.
- [ ] Hyperlink diff only covers text-run hyperlinks (`a:hlinkClick` on `rPr`) — not shape-level click-through hyperlinks (`a:hlinkClick` on `nvSpPr`/`cNvPr`) or hyperlinks on images/tables.

## Deck-level comparison
- [ ] `alignSlides`/`refineMoves` similarity threshold (0.12 match / 0.55 move) is a fixed heuristic — no tuning UI, and untested against real-world decks with many near-duplicate slides (e.g. templated report decks) where it may misalign.
- [ ] No detection of duplicated slides (same slide appearing twice in one deck) — alignment assumes roughly 1:1 content uniqueness.

## Reviewer workflow
- [ ] Merge plan is an *export* (JSON of choices) — there is no mechanism to actually apply the merge plan back into a new `.pptx` file. Full OOXML round-trip merge is unimplemented.

## Exports
- [ ] "Shareable link" is a self-contained `data:` URL copied to clipboard — NOT a real short/hosted link. Large decks could produce a very long URL (no size-limit handling/warning).
- [ ] Slack export is clipboard-only plain text — no real Slack API/webhook integration (would need OAuth + a backend, out of scope for a client-only DC).
- [ ] Email export uses `mailto:` — body length is subject to browser/OS mailto length limits; no truncation warning for large reports.
- [ ] No PPTX-native export of the diff overlay (e.g. an annotated copy of the After deck with change highlights baked in as shapes).

## Transitions
- [ ] "Transition preview" is a simplified generic crossfade swatch, not a per-type accurate animation (push/wipe/etc. all look the same motion-wise; only the label text differs).

## Testing / fixtures
- [ ] Red/Green TDD sample deck covers most categories but NOT: hyperlink-on-shape (only on text run), duplicate slides, section headers, OLE objects, real (non-dummy) audio/video content, theme-color (schemeClr) diffing beyond the basic map.
- [x] No automated test harness -- CLOSED (partial): an in-browser self-test suite (runSelfTests, triggered by a button) now covers the core algorithms plus a real merge-export round trip. Not a standalone CI-runnable suite.

## Accessibility / i18n
- [ ] No keyboard-only navigation audit (tab order through diff rows, approve/reject buttons, etc.).
- [x] Screen-reader labeling -- CLOSED (partial): aria-labels added to the highest-value icon-only controls (remove-reviewer, per-diff approve/reject, prev/next arrows); toast uses role=status/aria-live. Still no full audit (focus rings, tab order, every icon button).
- [ ] Single-language UI (English only); no RTL testing.

- [ ] Reviewer @mention notifications are in-memory + localStorage only -- no cross-device delivery (by design, no backend).
- [ ] The merged .pptx export's majority-vote logic gives no UI preview of which side won before download, and no per-slide override independent of per-diff picks.
- [ ] Self-test suite runs manually via a button click; not wired to CI or a pre-commit check.

## Newly identified gaps (this session)
- [ ] Keyboard shortcuts are not discoverable beyond a small toolbar hint string -- no full shortcuts help modal, no customization, and no indication of which shortcuts are active in batch view (most are no-ops there).
- [ ] Collapse-all/expand-all in All-pairs view is a single global toggle -- no per-filter-group collapse, and collapsed state is not persisted across a reload (unlike reviewer state).

## Newly identified gaps (this session)
- [ ] Notion/Confluence exports are file-download + manual-import only (by design, no backend) -- see GAP_CONTEXT.md. If real API push is ever requested, it needs a backend/OAuth flow, same as Slack/email.
- [ ] uiState in the JSON report export is one-way (export only) -- there's no 'import this report to restore UI state' path; a re-uploaded report JSON doesn't feed back into collapsedPairs/selectedPairs/mergeWinnerOverrides.
- [ ] Touch drag-to-reorder has no visual drag-preview/ghost element while dragging on touch (native HTML5 DnD gives one automatically on desktop; the manual touch implementation does not).

## Newly identified gaps (this session)
- [ ] Live push to Notion/Confluence will almost certainly fail from a real browser due to CORS (no backend proxy exists) — the feature is implemented "for real" and will work the moment a user runs it through an environment where CORS isn't blocking (e.g. a browser extension, a proxy, or if either vendor changes policy), but as shipped today it degrades to an error message pointing at the file-based export. This is NOT a bug to silently fix — a real fix requires a backend, which is out of scope unless requested.
- [x] Slack push delivery confirmation -- CLOSED (partial): switched from an opaque `mode:'no-cors'` fetch to a hidden form/iframe POST, whose load/error events distinguish 'request round-tripped' vs 'never went out'. Still not a true HTTP-status confirmation (iframe `load` fires for any response, including a 4xx/5xx from a bad/revoked webhook) -- see GAP_CONTEXT.md.
- [ ] Confluence push always APPENDS to the existing page body (via `<hr/>` + new content) rather than offering replace-vs-append as a choice.

## Newly identified gaps (this session)
- [ ] Slack iframe-based delivery confirmation cannot distinguish a genuine 2xx from an HTTP error response body that still loads in the iframe (e.g. a revoked webhook returning a 404 page) -- true confirmation would need a backend to read the actual status code.
- [ ] mergeReportPatch's conflict rule (current session always wins) is fixed/non-configurable -- a user who WANTS the imported file's decisions to win on conflict (e.g. importing a more authoritative reviewer's file) has no way to flip that preference; they'd have to Overwrite instead, losing their own unsaved-elsewhere choices.

## Newly identified gaps (this session)
- [ ] Reply delete is single-only -- no select-all/none or bulk-delete for replies within one comment's thread (unlike top-level comments, which have full bulk selection).
- [x] 'Clear decisions' scoping -- CLOSED: All / Only my votes / Specific reviewer / Specific slide range.

## Newly identified gaps (this session)
- [ ] 'Specific slide range' scope for clearing decisions uses row POSITION in the current All-pairs alignment order, not Before/After slide numbers -- if the alignment changes (e.g. after re-uploading a deck with different content), a previously-typed range no longer refers to the same slides. Not persisted across re-alignment, which is probably correct behavior but worth noting.
- [ ] No validation/clamping shown to the user if 'from' > 'to' in the slide-range inputs beyond the pure function's internal `Math.max(from, to)` clamp -- the UI doesn't visually indicate this happened.
- [ ] The reviewer-handle text input for 'Specific reviewer' scope has no autocomplete/dropdown against the actual reviewer list -- a typo'd handle silently clears nothing (matches no keys) rather than erroring.

## Newly identified gaps (this session)
- [ ] The Sensitivity slider and per-pair Ignore list are global (apply to ALL cross-deck duplicate detection everywhere: single-pair view panel, merge preview, batch mode) -- there's no per-context override (e.g. a looser threshold just for batch mode).
- [ ] 'Duplicate slide merging' only affects Before-only (removed) slides with a cross-deck duplicate -- it does not attempt anything symmetric for After-only (added) slides that might duplicate a Before slide's content in a different way (e.g. reordered AND slightly reworded).
- [ ] Batch mode's cross-dup count is a single number per pair with no drill-down (no way to see WHICH slides duplicated from the batch results table -- would need to open that pair into the full view).

## Packaging (newly identified gaps, this session)
- [ ] `pptxdiff` npm CLI (`bin/cli.js`) opens a browser tab, not a real native window (no dock/taskbar icon, no app-like process) -- not a true "desktop app" in the Electron/Tauri sense.
- [ ] The CLI still requires internet access at runtime (React/ReactDOM/Babel-standalone/pptx-renderer/JSZip/fonts all load from CDNs) -- doesn't work air-gapped/offline.
